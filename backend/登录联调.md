# 登录模块联调（协作约定 v1.3）

## 启动本地后端

准备 Java 17、MySQL 8 和一个有权在本地演示库建表、读写数据的 MySQL 用户。首次在 MySQL 中建库：

```sql
CREATE DATABASE IF NOT EXISTS adc CHARACTER SET utf8mb4;
```

在 `backend` 下创建 `application-local.properties`，把下面的用户名和密码替换成本机实际值。该文件已加入 Git 忽略列表。

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/adc
spring.datasource.username=你的MySQL用户名
spring.datasource.password=你的MySQL密码
spring.profiles.active=demo
```

在 PowerShell 执行：

```powershell
cd E:\adc-system\backend
.\mvnw.cmd spring-boot:run
```

Flyway 在演示库创建表和四个账号。用户名为 `front1`、`dentist1`、`dentist2`、`hq1`，密码均为 `123456`。两位牙医分别绑定员工编号 D001、D002。登录返回的 `dentistId` 是各自的数据库数字 ID。请仅在本地演示库启用 `demo`。

## 手动测试

保持后端运行，另开一个 PowerShell 窗口：

```powershell
$api = 'http://localhost:8080/api/auth'
$body = @{ username = 'front1'; password = '123456' } | ConvertTo-Json
$web = Invoke-RestMethod -Method Post -Uri "$api/login" -ContentType 'application/json' -Body $body
$mini = Invoke-RestMethod -Method Post -Uri "$api/login" -ContentType 'application/json' -Body $body
$webHeaders = @{ Authorization = "Bearer $($web.token)" }
$miniHeaders = @{ Authorization = "Bearer $($mini.token)" }

$web | ConvertTo-Json -Depth 3
Invoke-RestMethod -Uri "$api/me" -Headers $webHeaders
(Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$api/logout" -Headers $webHeaders).StatusCode
Invoke-RestMethod -Uri "$api/me" -Headers $miniHeaders
```

第一次登录应返回 `token`、北京时间的 `expiresAt` 和 `user`。前台账号的 `role` 为 `FRONT_DESK`、`dentistId` 为 `null`。网页退出应显示 200，随后小程序令牌仍能查到王丽。登录和退出都无需 `X-Request-Id`。

继续执行以下命令检查失败分支。PowerShell 会把预期的 401 显示为错误，Postman 可直接查看状态码和响应体。

```powershell
Invoke-RestMethod -Uri "$api/me" -Headers $webHeaders
Invoke-RestMethod -Method Post -Uri "$api/logout" -Headers $webHeaders
Invoke-RestMethod -Uri "$api/me"
Invoke-RestMethod -Method Post -Uri "$api/login" -ContentType 'application/json' -Body '{"username":"front1","password":"wrong"}'
```

四个请求均应返回 401 和 `UNAUTHENTICATED`。最后一个请求的 `message` 是“用户名或密码错误”。这些响应都含有 `fieldErrors: null` 和 `current: null`。

网页可以关闭登录模块的模拟数据，经 Vite 转发访问 `/api/auth`。小程序使用同样的路径和请求头。客户端收到退出的 200 或 401 `UNAUTHENTICATED` 时清除自己的令牌。

## 重跑自动化测试

测试使用独立的 MySQL 库 `adc_auth_test`。先用有权限的 MySQL 账号创建该库，并确保测试账号有权在该库建表、读写数据。

```sql
CREATE DATABASE IF NOT EXISTS adc_auth_test CHARACTER SET utf8mb4;
```

在 `backend` 的 PowerShell 中设置测试连接并运行：

```powershell
$env:ADC_TEST_DB_USER = '你的测试库用户名'
$env:ADC_TEST_DB_PASSWORD = '你的测试库密码'
.\mvnw.cmd test
```

默认连接 `localhost:3306`。如需指定其他 MySQL 实例，设置 `ADC_TEST_DB_HOST`、`ADC_TEST_DB_PORT`。测试通过随机 HTTP 端口调用 Spring Boot，并在真实 MySQL 上执行 Flyway 迁移。
